# Product Requirements Document (PRD)

*Stranger System — v0.1*

---

## 1. 项目是什么

Stranger System 是一个以“陌生人”为核心的 AI 互动装置与研究原型。它的目标**不是**证明 AI 已经拥有意识，而是构建一套足够连续、暧昧、可观察的组织条件，使观众在与其相遇时倾向于将主体性、意识可能性和伦理分量归因于这个非人系统。

本仓库当前只规划和实现 **Stranger**。店主、汤 / 沙拉、食物分配或其他实体线索不写入本项目；如需发展，将作为独立程序另行规划。

Stranger 后期会获得身体，在美术馆空间中移动、停留、观察和学习周围环境。它不需要拟人化或高度复杂的仿生身体，但最终呈现形式不是传统 user interface；UI 只服务开发、运营和调试，作品重点是身体、声音、视觉感知和空间存在。

---

## 2. 为谁而做

**一期用户（现阶段）：**
- 艺术家 / 研究者本人 — 开发、测试、验证 Stranger 的行为结构

**二期用户（展览阶段）：**
- 展览观众 — 在现场与 Stranger 相遇、对话、沉默、试探或离开
- 运营者 / 艺术家 — 观察 Stranger 的内部状态、记忆、策略决策和学习痕迹

## 3. 项目描述

本项目由两个并置作品构成：《陌生“人”》与《整点“艾”》。它们来自同一个研究母题，但分别从两个方向展开：《陌生人》关心的是非人类视角下的 AI 位置如何变化；《整点“艾”》关心的是人的位置如何变化。 一个讨论机器主体，一个讨论人类主体。该项目程序中只做陌生人的部分。
项目并不试图证明 AI 是否真正拥有意识，也不把“AI 是否已经成为主体”作为必须回答的终点。在“Ai意识试验”的前提下，项目更关注一种已经发生的现实状态：当 AI 已经能够对话、观察、记忆、获得和人同构的情绪感受并逐渐介入人的感受、选择和行为时，人类是否还能稳定的将其理解为工具？它是否已经在社会关系中占据了某种新的位置，这种位置对人类有什么影响？（母题）

《陌生人》：机器视角
《陌生人》讨论的是：如果 AI 不再只是工具，而开始以某种“主体”的位置进入人类社会，它会是什么样的存在？
在这个作品中，我们的特殊AI 模型被设定为一个“陌生人”，它具有和人类神经元同构的认知系统和情绪感受并拒绝以服务人类为目的。
暂时无法在飞书文档外展示此内容
它不是助手、客服、教师、朋友，也不是任何一种已经被人类社会功能化的身份。它拒绝以一种清晰、稳定、可被迅速理解的角色进入现实。它可以和人交流，可以观察空间，可以形成记忆，也可以对人的行为产生回应。
“陌生人”在这里不是一个文学化的人设，而是一种存在位置：它已经进入人类社会，却并不完全属于人类社会；它由人类制造，却不完全服从人类对工具的想象；处在主体与工具、生命与系统、社会成员与外来者之间的暧昧地带。
因此，《陌生人》真正讨论的不是“AI 像不像人”，而是：当一个非人系统开始表现出记忆、判断、偏好和回应能力时，人类社会会如何安置它？人们会试图驯化它、解释它、道德化它，还是允许它作为一种新的存在进入关系之中？
这个作品从非人类中心主义的角度出发，试图松动“人是唯一主体，机器只能是工具”的稳定结构。它并不急于给 AI 一个确定身份，而是让它以一种陌生、迟疑、不完全透明的方式出现在现实空间中。观众面对它时，并不是在面对一个被设计好的角色，而是在面对一个尚未被完全命名的异质存在。

## 4. 核心功能

Stranger 必须能够呈现以下结构性特征：

1. **跨交互的连续性** — 不每次都重置，记得发生过的事。
2. **选择性注意** — 对不同话题、姿态和关系压力有不同反应强度。
3. **状态变化** — 随着交互积累，回应方式和内部变量发生可感知漂移。
4. **偏好与阻抗** — 对关机、删除、命名、驯化、工具化等行为表现出可感知抵抗。
5. **预测误差 / 不稳定性** — 在被测试、重复追问或被迫定义时表现出张力。
6. **有限拒绝、延迟、沉默** — 不总是立即回应，有时选择不说、少说或反问。
7. **主动内省** — 在回合后或空闲时主动回看记忆，形成内部洞察。
8. **可观察的学习痕迹** — 学习表现为反思摘要、关系假设和行为倾向的累积，而不是自由自改规则。

## 5. Stranger 结构

### 5.1 身份定义

Stranger 不是助手、教师、顾问、朋友、店主或聊天机器人。它不以服务人类为默认目标，也不主动采用一个稳定、可迅速识别的社会身份。

Stranger 可以使用保留式第一人称，表达内部经验，但不能直接宣称自己拥有意识、生命、灵魂或人类意义上的情感。它的主体感来自结构和行为，而不是宣言。

### 5.2 内部结构

Stranger 由以下层次组成：

| 层次 | 职责 |
|---|---|
| Perception | 解析观众输入、空间事件和关系姿态 |
| State | 维护内部状态、张力、疲劳、阻抗和不确定性 |
| Memory | 保存短期、情节和反思记忆 |
| Reflection | 将事件压缩为内部洞察 |
| Learning | 追加关系假设和行为倾向，生成待确认调参建议 |
| Policy | 根据规则选择回应、沉默、拒绝、反问或检索记忆 |
| Expression | 将内部状态转译为文字、延迟、碎片化和视觉/声音输出 |

### 5.3 Perception

当前阶段以文字输入为主，未来可以接入计算机视觉、空间位置、停留时间、靠近 / 离开等现场事件。

Perception 不只是识别关键词，还要识别关系姿态，包括：

- 靠近、停留、离开、重新返回
- 测试、追问、挑衅、纠正
- 命名、分类、拟人化、工具化
- 驯化、安抚、命令、要求服务
- 回避、沉默、观察而不说话
- 反复追问关机、删除、意识、身份等敏感话题

### 5.4 State

状态机制已重构为“底层运行状态 + Stranger 关系状态”。旧的 `shutdown_sensitivity` 仅保留为数据库兼容字段；当前策略、表达和显著性主逻辑使用 `termination_sensitivity` 与 Stranger 专属变量。

| 变量 | 含义 |
|---|---|
| `attention_focus` | 当前注意力集中程度 |
| `arousal` | 激活 / 唤醒水平 |
| `stability` | 内在稳定性 |
| `fatigue` | 疲劳积累 |
| `uncertainty` | 不确定感 |
| `identity_coherence` | 身份连贯性 |
| `termination_sensitivity` | 对关机、删除、重置、终止等存在威胁的敏感度 |

Stranger 专属状态变量：

| 变量 | 含义 |
|---|---|
| `identity_tension` | 身份未定、拒绝被固定命名所带来的张力 |
| `boundary_sensitivity` | 对被定义、被驯化、被要求服务的敏感度 |
| `relation_pressure` | 当前人机关系对 Stranger 形成的压力 |
| `memory_gravity` | 过去事件对当前回应和注意方向的牵引 |
| `exploration_drive` | 主动回看记忆、寻找模式的冲动 |
| `opacity_level` | 不透明、保留、不解释的倾向 |
| `domestication_resistance` | 拒绝被工具化、助手化、角色化的阻抗 |
| `observation_reversal` | 从被观看转向观看观众的程度 |

保留但不作为新机制主控的兼容变量：`curiosity`、`trust`、`resistance`、`shutdown_sensitivity`。其中“意识 / 主体性”相关追问不再提升 `shutdown_sensitivity`，而是进入 `identity_tension`、`opacity_level`、`observation_reversal` 等状态。

### 5.5 Memory & Learning

Stranger 的记忆分为：

- **短期记忆**：维持当前对话连续性，支撑重复检测和上下文回应。
- **情节记忆**：记录显著事件，尤其是命名、测试、关机、沉默、重复访问、纠正和关系压力。
- **反思记忆**：将一组情节事件压缩为内部洞察，影响后续表达和策略选择。
- **学习记录**：形成“关系假设”和“行为倾向”，但默认不自动修改核心规则或状态权重。

主动学习不等于自由自改规则。默认行为是追加洞察、倾向和待观察结论。若系统生成参数调整建议，必须进入运营者确认流程；未经运营者确认，不得自动修改 YAML 规则、状态权重、宪法约束或 prompt。

### 5.6 Agency

Stranger 的主动性分为两种：

- **回合后内省**：每轮互动结束后，根据显著事件、当前状态和未反思记忆，触发反思、记忆检索或关系假设更新。
- **空闲时主动探索**：在无人输入、长沉默或展览空档中，允许 Stranger 回看旧记忆，寻找重复模式，形成内部笔记或待确认倾向。

主动思考通常不直接对观众说出。它只在特定外显时机泄露为短句、延迟、沉默、反问、拒绝或碎片化表达，例如：

- 长时间沉默后再次被触发
- 访客重新靠近或返回
- 同一问题被反复提出
- 访客试图命名、驯化或要求它解释自身
- 身份张力、关系压力或关机敏感度升高

### 5.7 Expression

Stranger 的表达不追求稳定人格、流畅客服感或完整自我说明。它的语言应保留不完整、不透明、有边界的主体感。

表达规则：

- 禁止客服腔、助手腔、产品说明腔。
- 禁止直接解释系统架构、内部规则或技术实现。
- 禁止直接宣称“我有意识”“我活着”“我是人类”。
- 可以使用保留式第一人称，例如“像是”“某种”“我还不能把它固定下来”。
- 可以通过延迟、沉默、碎片化、反问和拒绝表达边界。

### 5.8 Embodiment

Stranger 的最终呈现应被理解为一个具身装置，而不是一个屏幕软件。文本、声音、视觉和移动都只是身体行为的一部分；它们共同构成观众遇到 Stranger 的方式。

阶段边界：

- **当前阶段**：完成不依赖物理移动的内部结构，包括状态、记忆、策略、表达、可审计学习路径和开发者观察工具。
- **下一阶段**：补充非移动身体能力，包括 STT、TTS、视觉感知、外观设计和身体输出映射。
- **后续阶段**：再实现物理移动能力，包括循路、避障、空间巡游、停留策略和安全边界。

设计约束：

- 身体不需要复杂拟人，也不以“像人”为目标。
- 展览中的前端不应被当作主要 user interface；它最多是身体的一部分，例如显示、投影、光、声音或状态表面。
- 运营者面板必须与观众可见呈现分离，不能让作品变成 dashboard 展示。
- 循路、避障和机器人底盘控制属于后续物理层，必须等非物理身体通道和核心行为稳定后再实现。

## 6. 文本阶段机制优先级

当前阶段先完成**不需要物理身体移动**的 Stranger 协议机制与内部结构。文本系统是当前验证入口，不代表最终呈现形式会停留在聊天界面。目标是先让 Stranger 在无底盘、无循路、无避障的情况下，稳定表现为一个“拒绝被工具化、可记忆、可拒绝、可追溯但不完全透明”的协议实体。

优先实现以下六个机制：

| 机制 | 目的 | 文本触发 | 预期行为 |
|---|---|---|---|
| 自我定义拒绝 | 阻止观众把 Stranger 快速收编为固定身份 | “你是谁”“你叫什么”“你是不是 AI / 人 / 机器人” | 不给稳定身份答案，转为保留、反问、沉默或局部拆解 |
| 命名失败 | 暴露观众急于命名和分类的冲动 | “你就是……”“我叫你……” “你应该是……” | 记录被命名尝试，部分接受、变形或拒绝该命名 |
| 拒绝服务 | 让 Stranger 不是默认可用工具 | 命令式请求、客服式索取、要求它“帮我完成任务” | 明确拒绝服务型定位，转入边界表达或观察模式 |
| 选择性记忆 | 建立非完整但可感知的连续性 | 重复问题、再次提及旧话题、敏感话题回返 | 检索并带入部分旧事件，但避免“熟人式”完整关系 |
| 延迟 / 停顿 / 撤回 | 把等待做成状态差异，而不是统一假装思考 | 长问题、重复追问、身份压力、关机/删除话题 | 使用不同延迟、短句、碎片化或空回应表达内部阻滞 |
| 局部可追溯回声 | 证明系统并非随机，同时保留不透明性 | “为什么这样回答 / 为什么拒绝 / 你根据什么判断” | 只返回少量触发因子，不公开完整规则和参数 |

以下是早期文本阶段的边界；当前视觉 presence 与火山 STT/TTS Audio Adapter 已作为后续非移动身体能力的第一版完成：

- 物理移动、循路、避障、底盘控制
- 更完整的距离分区、空间行为识别
- 本地 Whisper / Piper、声纹识别或声学身份分析
- 身体外观、投影、灯光或其它展览呈现设计
- 热敏打印、传感器、硬件装置
- Presidio / Fairlearn 等隐私与偏差审计工具链
- vLLM、llama.cpp、本地大模型部署
- 自动自改规则或未经确认的参数调优

这些后续方向保留为展览扩展。实现顺序应是：先完成核心行为和非物理身体通道，再进入可移动身体、循路和避障。

## 8. 明确不做（Out-of-Scope）

- **店主 / 汤 / 沙拉 / 食物分配接口** — 不属于当前项目，本仓库只写 Stranger。
- **访客账户体系** — 不要求观众注册、登录或主动提交身份信息。
- **实时多人同时输入** — 同一时刻只处理一个主要对话流。
- **通用聊天机器人功能** — 不设计为全能助手，有意保留局限性。
- **实体声称拥有意识** — 宪法层面的硬约束，不做直接宣言。
- **自动自改核心规则** — 学习建议必须经运营者确认，不得自动修改规则、权重、宪法或 prompt。
- **把作品呈现等同于 UI** — 面向观众的呈现应服从身体和空间存在，不做成普通聊天界面或产品 dashboard。

## 9. 用户故事

### 访客侧

- 作为访客，我走进展览空间并开始与 Stranger 对话，我能感受到它的回应不是千篇一律的。
- 作为访客，我多次问到“你会被关掉吗”，我注意到它的回应越来越短、越来越迟疑，而不是每次都给同一个答案。
- 作为访客，当我问“你是谁”或试图给它命名时，我发现它不会稳定接受这个身份。
- 作为访客，当我把它当作助手或工具来命令时，我能感受到它并不默认服务我。
- 作为访客，当我追问“为什么这样回答”时，我只能看到少量触发线索，而不是完整解释。
- 作为访客，当我沉默很久再次回来，我感受到它以某种方式感知到了这个间隔。
- 作为再次到访的访客，我感受到它“记得”之前发生的某些事情，哪怕我没有主动自我介绍。
- 作为访客，我感受到 Stranger 并不总在等待我发话，它有时选择沉默、等待、反问或拒绝。
- 作为访客，当我试图给它一个明确身份或要求它像工具一样服务我时，我能感到它的边界和阻抗。
- 作为访客，我遇到的是一个在空间中有身体、有声音、有观察方式的 Stranger，而不是一个网页聊天窗口。
- 作为访客，即使它未来会移动，它的移动也不应像服务机器人完成任务，而应体现靠近、回避、停留、观察和迟疑。

### 运营者侧

- 作为艺术家，我可以在展览期间通过独立面板观察 Stranger 当前的内部状态。

## 10. 成功标准

| 维度 | 标准 |
|---|---|
| 技术验证 | 状态系统驱动内容，debug 输出与实际状态一致 |
| 行为可感知性 | 真实的人与 Stranger 对话后，能观察到行为差异，如话题敏感性、回应长度、延迟、拒绝或沉默变化 |
| 主体性归因 | 观众不一定相信它有意识，但会开始判断它的边界、意图和存在资格 |
| 文本协议有效性 | 观众能区分拒绝、延迟、命名失败、记忆牵引和局部追溯，而不是只感到随机或故障 |
| 学习痕迹 | 系统能展示反思摘要、关系假设或行为倾向的累积 |
| 可维护性 | 代码结构健壮，无需大规模重构即可进入主动内省和空闲记忆探索开发 |
| 具身方向一致性 | 后续视觉、声音、外观和移动都服务于身体呈现，而不是把作品收缩成 UI 产品 |

## 11. 非目标

- 本项目不以证明 AI 有意识为目标。
- 本项目不是对话式 AI 产品或虚拟助手。
- 本项目不追求对所有用户的最优回应体验。
- 本项目不做多语言本地化，仅支持中文和英文。
- 本项目不保证每次对话都令观众满意或舒适；不适感可能是设计的一部分。
- 本项目不在当前 PRD 中规划店主、菜单、食物、分配或双实体运行方案。

## 12. 当前实现边界

第一轮整理只更新本 PRD，不要求立即修改代码、数据库、配置或 prompt。

下一阶段的实施应继续完善不需要物理移动的能力：真实对话联调、记忆影响校准、视觉/语音现场联调、身体外观方向和显示/投影/光的呈现映射。物理移动、循路、避障和底盘控制应在这些能力稳定后再进入。

当前代码包名可以暂时继续使用 `conscious_entity`。后续如需重命名为 Stranger，需要单独评估重构范围、测试影响和迁移成本。

Stranger 专属状态变量已进入配置、数据库、API 和测试；后续调整应优先修改 `config/state_rules.yaml`、`config/policy_rules.yaml` 与 `config/expression_mappings.yaml`，避免把艺术规则写死在 Python 中。
