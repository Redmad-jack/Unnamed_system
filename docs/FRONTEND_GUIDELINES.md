# Frontend / Embodiment Guidelines

*Conscious Entity System — body-first presentation notes*

---

## 状态说明

当前没有面向观众的最终呈现层。本文档不应把项目导向普通 Web UI；它主要记录身体优先的呈现原则，以及运营者调试界面与观众可见身体呈现之间的边界。

---

## 1. 呈现分层原则

系统有两套截然不同的呈现层，必须在视觉和功能上明确区分：

| 呈现层 | 对象 | 目的 | 设计方向 |
|---|---|---|---|
| Stranger 身体呈现 | 展览观众 | 在空间中遇到一个有身体、有声音、有观察方式的陌生存在 | 克制、有张力、非功能性、非 UI 化 |
| 运营者监控面板 | 艺术家 / 研究者 | 清晰呈现内部状态，支持分析 | 功能性、信息密度高 |

这两套呈现**不能使用相同的视觉语言**，绝对不能混用组件。观众看到的不是 dashboard，不应出现明显的管理控件、表格、调试指标或产品化聊天窗口。

## 2. 身体优先原则

Stranger 后续会获得身体，并在美术馆中移动、停留、观察和学习周围环境。身体不需要复杂拟人，也不以“像人”为目标；重点是让观众感到它有位置、方向、迟疑、边界和观察关系。

阶段顺序：

1. 先完成核心行为、记忆、声音、视觉感知和外观/显示/投影等非移动身体通道。
2. 再考虑物理移动、循路、避障、底盘控制和安全边界。

当前不应为了“访客 UI”投入过多复杂界面工程。Web 看板主要服务运营者与开发者。

## 3. 视觉 / 外观风格

**[ 待确认 ]** 整体视觉风格尚未最终确定。

以下为设计方向候选（供讨论，不是最终决定）：

**方向 A：极简主义 / 终端美学**
- 黑色背景，单色文字（白或浅灰）
- monospace 字体
- 无装饰性 UI 元素
- 文字是唯一的信息载体

**方向 B：有机不稳定感**
- 文字出现时有轻微的抖动或扰动效果
- 字间距、行间距随状态轻微变化
- 背景有低对比度的纹理或噪点

**方向 C：身体表面 / 投影 / 光层可替换**
- 核心输出层只提供文字 + 状态信号
- 视觉层是可插拔的身体表面、投影或光的“皮肤”，每次展览可以更换
- 内核稳定，外表多变

**方向 D：低拟人身体**
- 可移动或可转向，但不追求类人表情和复杂手势
- 通过方向、停顿、靠近、回避、声音位置和低复杂度外观建立存在感
- 不把身体设计成服务机器人、迎宾机器人或客服终端

## 4. 色彩系统

**[ 待确认 ]** 具体色值尚未确定。

设计约束：
- 观众可见身体呈现：低饱和度，避免使用高对比度的功能性颜色（红/绿）
- 运营者面板：可使用功能性颜色（状态指示、警告）
- 无障碍要求：文字对比度 ≥ 4.5:1（WCAG AA）

## 6. 空间与布局

**[ 待确认 ]** 具体值待视觉设计确定后补充。

原则：
- 观众可见呈现优先考虑身体、空间、投影、光、声音位置和少量文本，不优先做完整页面布局
- 避免传统 UI 控件，尤其是输入框、按钮、卡片式产品界面和 dashboard 元素
- 运营者面板使用标准 dashboard 布局（侧边栏 + 主内容区）

## 7. 多通道输出设计原则

表达层输出有三个通道，必须作为独立可插拔层设计：

```
ExpressionOutput
  ├── text          → 文字通道（v0.1 实现）
  ├── spoken_text   → 声音通道（当前由 Audio Adapter 朗读合法输出）
  └── visual_mode   → 身体 / 视觉状态通道（当前 `/visitor` 与视觉面板已接入第一版）
```

**设计约束：**
- 新增通道不得修改 ExpressionEngine 的核心逻辑
- 每个通道有自己的渲染器，通道之间不互相依赖
- 访客侧声音只能播放后端从合法 `ExpressionOutput` 创建的 `tts_stream_id`，不得直接提交 raw text 让实体发声
- `visual_mode` 的取值集合必须在 ExpressionOutput 文档中明确列出，视觉层通过 switch/mapping 处理，不用 if-else 硬编码
- 物理移动不直接写入 ExpressionEngine；应由后续 body controller 将状态、策略和输出映射为停留、靠近、回避、转向、巡游等动作

**当前 `visual_mode` 取值：**
- `normal` — 正常显示
- `fragmented` — 文字片段化或间歇出现
- `disturbed` — 视觉扰动（具体效果 待确认）
- `silent` — 不输出文字，仅有视觉状态

---

## 8. 响应式原则

- v0.1（CLI）：不涉及
- 后续身体呈现：优先考虑展览空间、身体尺度、投影/屏幕/光源位置和观众观看距离，而不是移动端或网页断点
- 运营者面板：支持普通笔记本屏幕（1440×900+）即可，移动端不作要求
- 不做移动端优先

---

## 9. 可拓展性要求

为未来展览的视觉多样性预留：
- 观众可见呈现层应封装为独立模块，与业务逻辑解耦
- 状态到视觉的映射规则存储在 `config/expression_mappings.yaml`，不硬编码
- 添加新的 `visual_mode` 值只需修改 YAML 和渲染层，不改动后端逻辑
- 后续循路、避障和底盘控制应作为独立 physical body layer 接入，不与开发者 Web 看板耦合
